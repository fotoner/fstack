# 증거 블록

완료·정상·배포됨·고쳐짐을 보고할 때 붙이는 블록이다(CORE C15). 짧은 작업은 3줄이면 된다. 블록이 비어 있으면 "완료"라고 쓰지 않는다.

```markdown
**확인**
- [실물] <사용자 환경에서 한 확인: 명령과 출력 요지, 화면, 기기, 라이브 URL 응답>
- [합성] <fixture·임시 사본·에뮬레이션으로 한 확인>
- [코드] <코드·설정을 읽어 확인한 것>

**상태**
- 커밋 <sha> · 푸시 <원격 브랜치 또는 "안 함"> · PR <URL 또는 "없음"> · 머지 <예/아니오> · 배포 <예/아니오/사용자 몫>

**못 한 확인**
- <항목> — <이유>. 사람 확인: <무엇을 어떻게 보면 되는지 한 줄>
```

상태 조회 명령(추측하지 않고 조회한다). 원격 상태는 먼저 `git fetch --prune <remote>`가 성공해야 믿는다. 실패하면 원격 상태는 "미확인"으로 쓴다:

| 질문 | 명령 |
|---|---|
| 이 커밋이 원격에 있나 | `git branch -r --contains <sha>` |
| PR이 머지됐나, 최신인가 | `gh pr view <n> --json state,mergeStateStatus,headRefOid` |
| 웹이 새 버전을 서빙하나 | `curl -sI <url>`의 버전·ETag·배포 헤더, 또는 페이지의 빌드 표식 |
| Cloudflare 배포 상태 | `wrangler deployments list` / `wrangler pages deployment list` |
| 서비스가 떠 있나 | `systemctl status <unit>` 후 실제 요청 1회 |
| 새 셸에서 명령이 보이나 | `bash -lc 'command -v <cmd>'` (현재 셸 말고 새 로그인 셸) |
| 화면이 맞나 | 스크린샷을 직접 열어 보고, 모바일은 390px 폭도 본다 |
| CI가 녹색인가 | `gh pr checks <n>` (붙은 검사 전부, 0개면 0개라고 적는다) |

등급 판정:
- 하위 에이전트·원격 자식·예약 작업의 "됐다"는 `[보고]`다. 대조하기 전에는 위 칸에 올리지 않는다.
- "로그인됨"은 확인이 아니다. 그 인증으로 실제 API를 한 번 부른 결과가 확인이다.
- 실기기·실제 계정·라이브가 필요한데 할 수 없으면 ROUTING 3절 호스트 표로 할 수 있는 호스트를 먼저 찾는다(C10).
- 문서·설정 편집처럼 실행 효과를 주장하지 않는 작업은 `[코드]` 한 줄이면 된다.
