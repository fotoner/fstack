# wrap

세션은 남은 것을 드러내고 닫는다. 다시 열 때는 지정 사항을 잃지 않는다. 노트 저장소 기록은 그 저장소의 정본 스킬이 맡는다(ROUTING 6절).

## 1. 닫기 전 점검

작업한 저장소·worktree마다 읽기만 해서 모은다.

| 항목 | 명령 |
|---|---|
| 미커밋·미추적 | `git status --short` |
| 미푸시 | `git fetch --prune` 뒤 `git log --oneline @{u}..` |
| PR 상태 | `gh pr list --head <branch>` |
| 병합된 worktree·브랜치 | `git worktree list`, `git branch --merged` |
| 임시 산출물 | 이번 작업의 `/tmp/<작업명>-*` 목록 |
| 실행 중 작업 | 이번 세션이 띄운 백그라운드 명령·서버·Monitor |
| 위임·감시 | 진행 중인 `delegate_task`, `watch_pull_request` |
| 예약 | 이번 세션이 만든 예약 작업과 다음 실행 시각 |
| 못 한 확인 | `verify`가 남긴 미확인 항목 |

## 2. 정리 목록을 한 번에 승인받기

점검 결과로 할 일 목록을 만들어 **한 번에** 보여 주고 승인을 한 번만 받는다.

- 커밋·푸시할 것(`ship` 승인 사다리), 지울 worktree·임시 파일(원격 브랜치와 미커밋 worktree는 지우지 않는다), 멈출 감시(`unwatch_pull_request`)·예약, 보관할 T3 하위 스레드(이번 작업 것만).
- 못 한 확인은 **이월 항목**으로: 무엇을, 어떻게 확인하면 통과인지, 실패하면 무엇을 할지, 기한. 같은 대상의 이월 항목이 있으면 갱신한다. 위치는 저장소 규칙을 따른다(개인 저장소는 GitHub 확인 이슈). `walk` 킥오프가 기한이 된 것을 올린다.
- 승인 후 실행하고, 이슈·PR을 바꿨으면 다시 조회해 반영됐는지 확인한다.

## 3. 핸드오프

이어받을 일이 있으면 쓴다. 기본 위치는 작업 저장소나 저장소 밖 로컬 md 파일이다(ROUTING 6절).

```markdown
# 핸드오프: <작업>  (<날짜>, <호스트>)

## 목표
## 지금 상태          (증거 등급, 브랜치·worktree·PR·커밋 sha, 실행 중인 것과 ID)
## 다음 작업          (순서대로)
## 지정 사항          (사용자가 정한 모델·도구·환경·금지·승인 범위. 메모리에만 있는 규칙도 복사)
## 결정 대기
## 함정              (이번에 겪은 실패와 피하는 법)
## 확인 못 한 것·이월
## 문서 지도          (읽어야 할 파일 경로)
```

## 4. 이어받기 (다음 세션)

"이어서", "핸드오프 읽고 계속", 컨텍스트 압축 직후, 계정 전환 뒤에 쓴다.

1. 핸드오프와 지정 사항을 읽는다. 같은 작업을 잡은 다른 세션이 있는지 먼저 본다(C17).
2. 브랜치·worktree·PR의 현재 상태를 조회해 핸드오프와 다른 점을 찾는다. 오래된 기준 브랜치에서 이어 쓰지 않는다.
3. 남의 PR·브랜치·스레드를 이어받으면 원래 커밋과 작성자를 그대로 두고 PR 본문에 출처를 적는다. 이전 구현을 증거로 믿지 않고 다시 확인한다.
4. 지정 사항과 언어(C3·C7)를 다시 확인하고, 상태를 3줄로 보고한 뒤 이어간다. 사용자가 이어서 하라고 했으면 기다리지 않는다.

## 5. 브레인 기록

사용자가 브레인에 남기라고 하면, 이 스킬이 형식을 정하지 않는다. ROUTING 6절의 노트 저장소 지침에서 맞는 정본 스킬을 읽고 그대로 따른다. 저장 위치·커밋 방식도 그 스킬과 저장소 규칙을 따른다. 업무(회사) 내용은 그 저장소 규칙이 허락하는 곳에만 둔다.

## 6. 마지막 응답

```markdown
<한 줄: 무엇이 끝났고 무엇이 남았나>

| 저장소 | 커밋 | 푸시 | PR | 정리 | 남은 것 |
|---|---|---|---|---|---|

이월: <항목·기한 / 없음>
사람 확인: <항목 / 없음>
```
