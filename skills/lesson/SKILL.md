# lesson

교정은 지금 지키고, 후보로 남기고, 승인을 거쳐 가장 강한 수단으로 올린다. 규칙의 효과는 재발 횟수로 잰다. 한 번 나온 취향을 모든 작업의 규칙으로 넓히지 않는다.

## 즉시 모드 (교정을 받았을 때)

1. **같은 턴에 먼저 고친다.** 사과만 하고 멈추지 않는다.
2. **규칙 한 줄**로 바꾼다: "무엇을 할 때, 무엇을 한다/하지 않는다". 사용자의 원래 말은 근거 칸에 짧게 남긴다.
3. **적용 범위**를 발화에서 읽는다.
   - 범위 표시가 없거나 애매하면 → 이번 작업에만 적용한다.
   - "이 저장소에서는" → 그 저장소.
   - "앞으로는", "항상", "지시 안 하면 ~로" → 지속 규칙 후보.
4. **후보로 기록**: `~/dev/fstack/local/lessons.md` 규칙표에 후보 행을 더한다(로컬 파일 변경. 커밋은 승인 뒤).
5. **지속 규칙이면 수정안을 같은 응답에 낸다**: 어느 파일의 어느 줄을 어떻게 바꿀지 정확히 보이고, 강제 수단 순위를 적는다. 사용자가 `ㄱ`하면 반영한다. 훅·전역 설정은 권한 확대라 명시 승인 없이는 바꾸지 않는다(C8).

| 순위 | 수단 | 예 |
|---|---|---|
| 1 | 훅·검사·스크립트(어기면 멈춤) | `~/dev/fstack/tools/hooks/fstack_guard.py`(이름·패턴 kill 차단, 위임 모델 인자 누락 차단), validator 규칙, pre-push 비밀값 스캔 |
| 2 | 스킬 절차의 단계 | `ship` 절차에 단계 추가 |
| 3 | `CORE.md` 규칙 또는 `ROUTING.md` 값 | 모델 금지 목록, 역할 기본값 |
| 4 | 저장소 `AGENTS.md` | 저장소별 금지 경로 |
| 5 | 에이전트 메모리 | 사건 맥락 보관용. 규칙의 유일한 위치로 쓰지 않는다 |

6. **보고**: "규칙 후보: <한 줄> (범위) — 수정안: <위치> / 반영함·승인 대기".

## 규칙표 (`~/dev/fstack/local/lessons.md`)

| 날짜 | 규칙 | 범위 | 강제 수단(위치) | 근거 사례 | 재발 |
|---|---|---|---|---|---|

- 규칙 ID를 적을 때는 "C17(모델)"처럼 이름을 함께 쓴다.
- "재발" 열은 같은 규칙이 다시 어겨졌을 때 날짜와 함께 채운다. 강제 수단이 3~5순위인 규칙이 재발하면 한 단계 위로 올리는 안을 낸다.
- 강제 수단이 없는 규칙은 "없음"으로 드러낸다.

## 주기 모드 ("교정 분석해줘", "fstack 갱신")

1. ROUTING 6절의 세션 로그 추출 도구로 호스트별 "직전 응답 → 다음 사람 요청" 쌍을 뽑는다. 다른 호스트는 원격 위임으로 그 호스트에서 돌리고 요약만 받는다(ROUTING 3절). 원문은 `/tmp`에만 두고 커밋하지 않는다. 키워드 표시는 거친 힌트일 뿐이라 표시 없는 쌍도 읽는다.
2. 쌍을 `~/dev/fstack/docs/design.md`의 실패 분류(F1~F19)로 판정한다.
3. **두 번 이상** 나온 분류와 후보 행만 다룬다. 한 번 말하고 다른 때 반대로 말한 선호는 잡음으로 둔다.
4. 규칙표의 재발 열을 갱신한다. 규칙을 만든 뒤에도 줄지 않은 분류는 강제 수단을 올리는 안을 낸다.
5. 여러 저장소 메모리에 같은 규칙이 반복 저장돼 있으면(예: 한국어, 아티팩트 금지) 전역 한 곳으로 모으는 안을 낸다.
6. 개정안은 새 스킬보다 기존 스킬의 단계 추가를, 새 규칙보다 기존 규칙의 수정을 먼저 고른다. 호출 기록이 없는 스킬·규칙은 지우는 안을 같이 낸다. CORE 예산(`check_fstack.py`)을 넘기지 않는다.
7. 개정안은 `council`(`design` 모드)로 검토받고 사용자 승인 후 반영한다.

## 바꾼 뒤 (smoke)

- 새로 만들거나 고친 스킬은 그날 한 번 실제로 실행해 본다. 절차가 끊겼거나 참조 파일이 없는 결함은 실행해야 드러났다.
- `python3 -I ~/dev/fstack/tools/check_fstack.py`로 형식·참조·크기 예산을 확인한다.
- CORE를 바꿨으면 `~/dev/fstack/install.sh --apply`로 각 하네스의 관리 블록을 갱신하고 `check_fstack.py --installed`로 확인한다.
- 커밋은 승인된 경우에만 한다. 승인이 없으면 변경과 검증 결과를 보고하고 커밋을 제안한다. 미커밋 변경이 쌓이면 되돌릴 정본이 없으니 제안을 미루지 않는다.
- 지침 텍스트를 바꿀 때는 가능하면 과거 교정 쌍 몇 개로, 고친 지침에서 같은 실수가 나오지 않는지와 정상 요청이 과하게 막히지 않는지(대조군)를 함께 본다.

## 하지 않는 것

- 메모리에만 규칙을 남기고 끝내지 않는다.
- 범위가 애매한 교정을 전역 규칙으로 만들지 않는다.
- 규칙을 계속 쌓기만 하지 않는다. CORE·저장소 지침이 커지면 지도와 불변식만 남기고 나머지는 스킬로 옮긴다(`harness`).
