# 깊은 조사 노트

주제 하나를 질문 묶음(갈래)으로 나누어 병렬로 조사하고, 갈래마다 노트 파일 하나를 남긴 뒤, 노트를 근거로 최종 보고서를 합성한다. 기획서나 구현 계획(`council` plan)의 근거 자료를 만드는 단계이며, 영상은 `references/video.md`로 따로 본다.

## 언제 쓰는가

- 결정 전에 외부 사실(API 사양, 가격, 약관, 경쟁 사례)을 근거와 함께 모아야 할 때.
- 질문이 여러 영역에 걸쳐 한 사람이 순서대로 하면 오래 걸릴 때.
- 한두 가지 사실만 확인하면 되는 경우에는 쓰지 않는다. 직접 검색하고 답한다.

## 산출물과 위치

프로젝트에 관례가 있으면 그것을 따른다. 없으면 다음 구조를 쓴다.

| 산출물 | 위치 | 설명 |
|---|---|---|
| 조사 노트 | `research_notes/<주제>/<갈래>.md` | 갈래당 파일 하나. 영어 snake_case 파일명을 권장한다 |
| 영상 노트 | `research_notes/<주제>/videos/<영상ID>.md` | `references/video.md` 절차로 만든다 |
| 최종 보고서 | `reports/<주제>.md` | 노트를 근거로 합성한 문서 |

조사 노트와 보고서는 코드 저장소 밖(조사 전용 저장소)에 둘 수 있다. 기획서가 노트를 인용할 때는 노트 파일 이름을 근거 표기로 쓴다.

## 절차

### 1. 갈래 설계 (오케스트레이터)

1. 사용자의 목적과 이 조사로 내릴 결정을 한두 문장으로 적는다. 결정과 관계없는 질문은 뺀다.
2. 질문을 갈래로 묶는다. 갈래 하나는 질문 5~10개 이하이고, 갈래끼리 겹치지 않아야 한다. 겹치는 질문은 한쪽에만 둔다.
3. 갈래마다 다음을 정한다: 파일 이름, 질문 목록, 우선 확인할 공식 출처, 검색·열람 예산(5절), 배정 모델.
4. 이미 있는 노트가 있으면 새로 조사하지 말고 읽어서 질문에서 뺀다. 오래된 노트(확인일이 한 달 넘음)는 가격·버전·정책 항목만 다시 확인한다.
5. 사용자가 확인해야 하는 갈래 구성이나 범위가 애매하면 이 단계에서 묻는다. 하위 작업자를 띄운 뒤에는 방향을 바꾸기 어렵다.

### 2. 병렬 조사 (하위 작업자)

- 갈래마다 하위 작업자를 하나씩 띄운다. 작업 지시서는 `templates/subtask-brief.md`를 채워서 쓴다.
- Claude 계정이 여럿이면 갈래를 계정에 나누어 배정한다. 같은 회사 모델끼리만 검토하지 않도록, 결정 영향이 큰 갈래는 3단계에서 다른 회사 모델로 교차 확인한다.
- 작업자는 노트 파일 하나만 쓴다. 다른 갈래의 노트, 프로젝트 코드, 기획서는 고치지 않는다.
- 작업자의 기본 금지 사항: 로그인, 가입, 결제, CAPTCHA 우회, 비공식 스크래퍼 사용, 비밀값 기록, 제3자 개인정보 저장.

### 3. 교차 확인 (선택, 권장)

- 결정에 직접 영향을 주는 주장(가격, 한도, 약관 허용 여부, 지원 여부)만 골라 다른 회사 모델에게 재확인을 맡긴다. 노트 전체를 다시 조사시키지 않는다.
- 재확인 요청에는 주장 문장, 원래 출처, "원문을 직접 열어 일치 여부와 확인일을 적을 것"만 담는다.
- 결과가 다르면 노트를 지우지 말고 `Gaps`에 충돌 사실과 어느 쪽을 택했는지, 이유를 적는다. 공식 문서와 블로그가 충돌하면 공식 문서를 우선한다.

### 4. 노트 검수 (오케스트레이터)

노트를 받으면 다음을 직접 확인한다. 하나라도 어긋나면 해당 작업자에게 되돌린다.

- 모든 `Cited Findings` 항목에 출처 링크와 확인 방식이 있는가.
- 본문에 인용한 숫자·날짜를 출처에서 무작위로 3개 골라 직접 열어 대조했는가. 결과를 노트에 쓰지 않아도 되지만 최소 한 번은 직접 연다.
- `Inferences`가 `Cited Findings`와 섞여 있지 않은가.
- 확인하지 못한 질문이 조용히 사라지지 않고 `Gaps`에 남았는가.
- 비밀값, 로그인 후 화면, 타인의 개인정보가 들어가지 않았는가.

### 5. 검색 한도 관리

검색과 열람에는 한도가 있다(도구별 호출 수, 시간당 속도 제한, 모델 사용량). 한도를 숨기지 않고 계획에 포함한다.

- 갈래마다 예산을 정해 지시서에 적는다. 예: "검색 25회, 페이지 열람 40회 이내". 정해진 수치가 없으면 질문당 검색 3회, 열람 5회 정도를 출발점으로 쓴다.
- 작업자는 노트 맨 위 블록에 사용량을 적는다(검색 N회, 열람 M회).
- 한도에 닿으면 멈추고, 확인하지 못한 질문을 `Gaps`에 "한도로 확인하지 못함"이라고 적는다. 우회하지 않는다.
- 같은 문서를 갈래마다 반복해서 열지 않는다. 공통 출처(공식 문서 첫 페이지, 가격표)는 오케스트레이터가 먼저 한 번 읽고 요약을 지시서에 넣는다.
- 요약기를 거치는 열람 도구는 원문을 줄여 전달한다. 따옴표 안의 문장이 원문과 글자 단위로 같다고 보장되지 않으므로, 결정에 중요한 문장은 `[원문]`으로 다시 확인한다.
- 병렬 작업자 수는 계정별 사용량 한도를 넘지 않게 정한다. 한 계정이 한도에 가까우면 다른 계정이나 Codex로 갈래를 옮긴다.

### 6. 최종 보고서 합성

모든 노트가 검수를 통과한 뒤 `templates/final-report.md` 구조로 합성한다.

- 제목은 주제 이름이 아니라 **결론 문장**으로 쓴다. 예: "일본 소식 봇은 승인 큐부터 시작한다".
- 첫 문단에 결론과 기준일을 쓴다. 독자가 첫 문단만 읽어도 결정을 알 수 있어야 한다.
- 소제목도 주장 문장으로 쓴다. 각 절은 근거 표나 비교표를 포함하고, 숫자와 주장마다 출처 링크를 붙인다.
- 엇갈리는 수치는 한 절에 모아 "구현 전에 직접 확인한다" 항목으로 보낸다.
- 노트의 `Inferences`를 보고서에 옮길 때는 "추론"이라고 밝힌다. 근거 없이 단정하지 않는다.
- 마지막 `Conclusion`에는 결정, 남은 위험, 다음 확인 항목을 쓴다.
- 보고서에 쓴 모든 주장은 노트 중 하나에서 추적할 수 있어야 한다. 노트에 없는 주장을 새로 만들지 않는다.

## 노트 형식 요약

자세한 양식은 `templates/note.md`에 있다.

```text
# <갈래 제목>
> 기준일, 확인 방법, 표기 규칙, 검색 사용량
## Q1. <질문>
### Takeaway     결론 한두 문장
### Cited Findings   출처가 붙은 사실 목록 (- 사실 설명. (출처: [이름](URL), [원문|요약|스니펫], 확인일))
### Inferences   노트 작성자의 추론 (근거 사실을 지목한다)
### Gaps         확인하지 못한 것, 출처끼리 충돌한 것, 한도로 못 본 것
## Q2. ...
```

확인 방식 표기:

| 표기 | 뜻 |
|---|---|
| `[원문]` | 공식 문서나 소스를 직접 내려받아 원문 텍스트로 읽었다 |
| `[요약]` | 요약기를 거치는 도구(WebFetch 등)로 페이지를 읽었다 |
| `[스니펫]` | 검색 결과의 요약 문장만 봤고 페이지는 열지 않았다 |
| `[실행]` | 직접 명령이나 스크립트를 실행해서 확인했다 |

`[스니펫]`만 있는 사실은 결정의 근거로 쓰지 않는다. 쓰려면 먼저 페이지를 열어 표기를 바꾼다.

## 쓰기 규칙

- 사실과 추론을 분리한다. 사실은 `Cited Findings`, 추론은 `Inferences`에만 둔다.
- 한국어 문장은 완결된 문장으로 쓰고, 과장 표현(압도적, 획기적)과 본문 엠대시를 쓰지 않는다.
- 기준일을 노트 맨 위와 가격·버전·정책이 나오는 항목에 적는다. 확인일이 없는 가격은 쓰지 않는다.
- 출처 하나에는 URL이 하나 있어야 한다. "공식 문서에 따르면"만 쓰고 링크를 빼지 않는다.
- 인용한 외국어 문장은 원문을 그대로 두고 한국어 설명을 덧붙인다.
- 서로 다른 출처의 수치가 다르면 둘 다 적고 `Gaps`에서 비교한다.
- 비밀값, 토큰, 계정 식별자, 로그인 후에만 보이는 정보는 적지 않는다. 화면에서 본 값이어도 옮기지 않는다.
- 노트 사이에는 `[[갈래이름]]`이나 상대 경로 링크로 서로 참조한다. 같은 사실을 두 노트에 복사하지 말고 한 곳에 두고 링크한다.

## 완료 기준

- 모든 갈래 노트가 4절 검수를 통과했다.
- 교차 확인 대상으로 정한 주장 모두에 결과(일치, 불일치, 확인 불가)가 기록되어 있다.
- 최종 보고서가 있으면 모든 주장이 노트에서 추적된다.
- 하지 못한 조사(한도, 접근 불가, 시간)가 `Gaps`와 최종 응답에 적혀 있다.

## 하위 작업이 실패했을 때

- 작업자가 노트를 쓰지 못하고 끝났으면 같은 지시서로 한 번만 다시 시도한다. 두 번째도 실패하면 갈래를 줄이거나 오케스트레이터가 직접 조사한다.
- 작업자가 형식을 어겼으면 파일을 새로 만들지 말고 어긋난 항목을 지적해서 고치게 한다.
- 검수 중 근거가 없는 사실을 발견하면 노트에서 지우지 말고 `Gaps`로 옮기거나 `[스니펫]`으로 표기를 낮춘다.
