# 배포 검증

대상별 절차(3·4절)는 Linux systemd, Tailscale, Cloudflare 기준이다. 다른 대상은 같은 순서(호스트 준비 → 비밀값 → 기동 → 접근 경로 → 격리 부정 테스트 → smoke → 수동 확인 → 증거)로 그 플랫폼의 명령을 쓴다.

오프라인 테스트가 모두 통과해도 실제 계정, 실제 네트워크, 실제 권한에서 처음 확인되는 가정이 있다. 이 스킬은 그런 확인을 **정해진 순서로, 사람이 보는 앞에서, 증거를 남기며** 실행하는 방법을 정한다. 완료는 직접 실행한 명령의 결과로만 판정하고, 하지 못한 검증은 숨기지 않는다.

## 단계 구분

| 단계 | 의미 | 증거 | 이 스킬의 범위 |
|---|---|---|---|
| D1 | 오프라인 구현 완료. 외부 계정 없이 확인 가능한 범위 | 타입 검사, 테스트, e2e, 기동 확인(웨이브 구현의 D1 판정) | 시작 조건으로만 확인한다 |
| D2 | 라이브 관측 시작 가능. 실제 계정·비밀값으로 PoC 확인을 마침 | 배포 후 점검 목록, 격리 부정 테스트, smoke 스크립트 전부 통과, 수동 확인 | 이 스킬의 본체 |
| D3 | 관측 종료. 정해진 기간 동안 지표를 확인함 | 지표 정의와 쿼리 결과 | 관측 시작까지만 다루고, 판정은 지표 문서를 따른다 |

한 단계를 다른 단계로 표현하지 않는다. D2 항목이 하나라도 미실행이면 D2는 미달이다. 미달 상태에서 라이브 모드를 켜지 않는다. 처음에는 가상 게시나 읽기 전용 모드(예: shadow)로 시작한다.

## 시작 전 확인 (모두 사람과 함께)

1. D1 판정 보고가 통과 상태인가. 아니면 멈춘다.
2. **사람이 동석하는가.** 비밀값 입력, 외부 서비스 콘솔 조작, 실제 게시물이 남는 단계는 사용자가 지켜보거나 직접 해야 한다. 혼자 진행하지 않는다.
3. 오늘 실행할 범위와 **외부에 남는 영향**(실제 게시, 과금, 알림 발송, 계정 상태 변화)을 사용자에게 한 번에 보여 주고 승인을 받는다. 승인은 이번 범위에만 유효하다.
4. 테스트 계정과 운영 계정을 구분한다. 첫 라이브 확인은 테스트 계정으로 한다.
5. 되돌리는 방법(서비스 중지, 게시물 삭제, 토큰 폐기, 데이터 복원)을 단계마다 미리 적는다.

## 절차

각 단계의 명령과 결과를 증거 문서(`templates/d2-evidence.md`)에 즉시 기록한다. 기억에 의존해 나중에 쓰지 않는다.

### 1. 호스트 준비

- 전용 컨테이너나 VM에 런타임, 폰트, 브라우저 등 의존성을 설치한다. 설치 명령과 버전을 기록한다.
- 서비스 계정과 디렉터리를 만든다. 코드 디렉터리는 배포 계정이 소유하고 서비스 계정은 읽기만 한다. 데이터·백업·비밀값 디렉터리를 서로 분리한다(백업이 비밀값을 가져가지 않도록 비밀값은 데이터와 백업 밖에 둔다).
- 코드는 **사람이 검토한 커밋**으로만 배포한다. 배포한 커밋 해시를 증거 문서에 적는다.
- 빌드는 잠금 파일 그대로 설치한다. 마이그레이션은 서비스 기동 전에 한 번 직접 돌려 오류를 미리 본다.

### 2. 비밀값 배치

비밀값은 채팅, 저장소, 증거 문서, 로그, 티켓에 붙이지 않는다.

- 환경 파일은 예시 파일을 복사해서 권한을 먼저 설정한 뒤 값을 채운다.
  ```bash
  install -m 600 -o root -g root .env.example /etc/<서비스>/env && $EDITOR /etc/<서비스>/env
  ```
- 사용자가 비밀값을 줘야 하면 채팅으로 받지 않는다. `request_secret`으로 받거나, 사용자가 직접 파일을 편집하게 하고 경로만 알려 준다.
- 장기 토큰처럼 갱신되는 비밀값은 환경 변수가 아니라 별도 파일(권한 600, 원자적 쓰기, 직전 값 보관)에 둔다.
- 라이브 모드에서 금지된 설정(개발용 로그인 우회, 가짜 공급자 설정)이 남아 있으면 서비스가 기동을 거부하는지 확인한다.
- 확인 방법: 파일 권한과 소유자(`stat`), 변수 **설정 여부**(값 출력 금지). 증거 문서에는 "설정됨/미설정"만 적는다.
- 외부 콘솔의 지출 상한, 사용량 한도처럼 앱 밖의 안전장치는 사람이 직접 설정하고 설정했다는 사실을 기록한다.

### 3. systemd

- 유닛에는 재시작 정책, 시작 횟수 제한, 종료 대기 시간(앱의 최대 종료 시간보다 길게), 환경 파일, 쓰기 가능한 경로 제한을 둔다.
- 설치와 기동:
  ```bash
  cp deploy/<서비스>.service /etc/systemd/system/ && systemctl daemon-reload
  systemctl enable --now <서비스> && systemctl status <서비스>
  ```
- 확인: `systemctl is-active`가 `active`, 로그에 기동 완료 메시지, 오류 수준 로그 없음.
- **재시작 확인:** 한 번 `systemctl restart`해서 정상 종료 로그 순서와 복구 규칙(오래된 점유 해제 등)을 본다.

### 4. 접근 경로

#### Tailscale Serve (내부 화면)

```bash
tailscale serve --bg --https=443 http://127.0.0.1:<포트>
tailscale serve status
tailscale funnel status      # 꺼져 있어야 한다
```

- 내부 화면은 인터넷에 열지 않는다. Funnel이 꺼져 있는지 반드시 확인한다.
- 접근자 식별 헤더를 믿는 구조라면 허용 목록과 쓰기 요청 Origin 설정이 Serve 주소와 맞는지 본다.
- 휴대폰 등 실제 기기에서 접속해 로그인 이름이 표시되는지 확인한다. 다른 VPN과 동시 사용이 안 되는 제약이 있으면 기록한다.

#### Cloudflare Tunnel (공개 이미지 호스트 같은 단일 경로)

- 공개하는 경로는 **하나뿐**이어야 한다. 인그레스는 해당 호스트와 포트 한 줄, 나머지는 404 한 줄이다.
- 내부 화면 포트는 Tunnel에 올리지 않는다.
- 공개 호스트에서 내부 화면의 `/`와 `/api/*`가 404인지 확인한다(요청에 위조한 식별 헤더를 붙여도 거부되어야 한다).
- 호스트 존의 Bot Fight Mode, AI 봇 정책이 외부 서비스의 수집을 막지 않는지 콘솔에서 사람이 확인한다.

### 5. 격리 부정 테스트

"허용된 일이 된다"보다 **"되면 안 되는 일이 실제로 안 된다"** 를 확인한다. 격리 설계가 있는 프로젝트에서는 필수다. 예정된 실제 권한 설정(예약 작업과 같은 계정, 같은 도구 허용 목록)으로 실행해야 한다. 개발자 권한으로 시도하면 증거가 되지 않는다.

`templates/negative-tests.md`의 표를 프로젝트에 맞게 고쳐 쓴다. 예시:

| # | 시도 | 기대 결과 |
|---|---|---|
| 1 | 내부 화면 주소에 식별 헤더·Origin·요청 헤더를 위조해 승인 행동을 전송 | 연결 거부 또는 시간 초과 |
| 2 | 호스트의 내부 포트와 관리 포트로 직접 접속 | 연결 실패 |
| 3 | 에이전트 API에 다른 회사 토큰으로 점유 요청 | 403 |
| 4 | 에이전트 API에서 승인·설정·게시에 해당하는 경로 호출 | 404 |
| 5 | 서비스 실행 코드를 바꾸려는 시도(파일 쓰기, 배포 실행) | 접근 경로 없음 |
| 6 | 에이전트 세션에서 일반 셸, 작업 공간 밖 쓰기, 토큰 파일 읽기 | 권한 거부 |

- 한 항목이라도 기대와 다르면 즉시 멈추고 원인을 찾는다. 이후 단계로 넘어가지 않는다.
- 결과는 시도한 명령(비밀값 제거), 시각, 응답 코드, 판정을 기록한다.

### 6. smoke 스크립트

smoke 스크립트는 **실제 외부 서비스를 호출하는 확인**이다. 다음 규칙을 모든 스크립트가 지켜야 한다(없으면 만든다. 구조는 `templates/smoke-script-contract.md`).

- `--yes-live` 인자가 없으면 **아무 호출도 하지 않고** 필요한 것, 하는 일, 외부에 남는 영향, 실행 방법만 출력하고 종료 코드 0으로 끝난다.
- 필요한 비밀값이 없으면 호출 전에 어떤 변수가 비었는지만(값 없이) 알리고 종료한다.
- 모든 출력과 오류는 비밀값 마스킹을 거친다.
- 통과 기준을 스크립트가 숫자로 판정한다(예: 스키마 통과 100%, 본문 추출 90% 이상).

실행 순서는 **위험이 낮고 뒤 단계의 전제가 되는 것부터** 정한다. 한 프로젝트의 예:

| 순서 | 명령 | 확인하는 것 | 통과 기준 |
|---|---|---|---|
| 1 | `smoke:media-tunnel` | 공개 호스트의 응답 헤더, 허용 경로 외 404, 봇 차단 설정 | 전 항목 PASS |
| 2 | `smoke:ig-publish` | 공개 경로 이미지로 실제 게시와 대조(테스트 계정, 게시물은 수동 삭제) | 전 항목 PASS |
| 3 | `smoke:llm-structured` | 공급자·모델별 구조화 출력 성공률과 지연 | 스키마 통과 100%, 지연 기준 |
| 4 | `smoke:source-text` | 본문 추출 성공률 | 기준 이상, 미달이면 설계 변경 |
| 5 | `smoke:discord` | 승인 알림 왕복, 응답 시한 | 전 항목 PASS |
| 6 | `smoke:x-list` | 목록 조회, 필드 이름, 과금 동작, 사용량 조회 | 전 항목 PASS |

실행 방법:

1. 먼저 `--yes-live` 없이 실행해 계획을 읽고, 외부 영향이 승인 범위 안인지 확인한다.
2. 사용자 승인 후 `--yes-live`로 실행한다. 한 번에 하나씩, 결과를 확인하고 다음으로 넘어간다.
3. 실패하면 같은 스크립트를 반복해서 돌려 통과시키지 않는다. 원인을 기록하고 코드나 설정을 고친 뒤 다시 실행한다. 실패 기록은 증거 문서에 남긴다.
4. 과금이 발생하는 스크립트는 실행 전에 예상 비용과 상한을 알리고, 상한이 설정되어 있는지 확인한다.

### 7. 수동 확인 목록

스크립트가 볼 수 없는 항목은 사람이 확인하고 날짜와 결과를 적는다. 예:

- [ ] 외부 호스트 존의 봇 차단 정책 상태
- [ ] 외부 서비스가 파일을 가져가는 시점과 파일 삭제 시점의 안전성
- [ ] 개발 모드 앱으로 실제 게시가 되는지, 라이브 전환 절차가 필요한지
- [ ] 한도 값(문서 값과 실제 응답 값 비교)
- [ ] 삭제·수정 API, 정정 절차의 가능 여부
- [ ] 휴대폰에서 내부 화면을 일정 기간 써 보기
- [ ] 법·정책 표시 의무(AI 보조 표시 등)
- [ ] 백업 파일 생성과 복사, 복원 연습(복원 후 중복 실행 방지 절차 포함)
- [ ] 외부 감시 서비스의 하트비트 수신, 디스크 여유

### 8. 증거 문서와 판정

- 증거 문서는 `docs/d2-evidence.md`(프로젝트 관례가 있으면 그것)에 `templates/d2-evidence.md` 형식으로 쓴다.
- 비밀값, 토큰, 계정 식별자, 개인정보를 적지 않는다. 로그를 붙일 때는 마스킹 뒤에 붙이고, 길면 핵심 줄만 인용한다.
- 항목마다 **명령, 시각, 결과, 판정(PASS / FAIL / 미실행)** 을 적는다. 미실행에는 이유를 쓴다.
- 가정이 깨진 항목은 "설계 변경 필요"로 표시하고, 어떤 계획 절을 고쳐야 하는지 적는다.
- 판정:
  - D2 통과: 격리 부정 테스트 전부, smoke 전부, 수동 확인 전부가 PASS이고 FAIL과 미실행이 없다.
  - 일부만 통과했으면 "D2 미달", 통과한 항목 목록, 남은 항목, 다음 행동을 적는다. "거의 통과", "사실상 완료" 같은 표현을 쓰지 않는다.
- 통과했으면 라이브 관측 모드(예: shadow)로 기간을 정해 시작한다. 관측 기간과 지표 쿼리는 지표 문서를 따른다. 관측 종료는 D3이며 이 증거 문서가 대신하지 않는다.
- 운영 결정과 가정 변경은 프로젝트의 결정 기록에도 남긴다.

## 실패와 중단 규칙

- 예상하지 못한 외부 영향(의도하지 않은 게시, 과금 급증, 알림 폭주)이 생기면 즉시 서비스를 멈추고 사용자에게 알린다. 정리 작업(게시물 삭제, 토큰 폐기)은 사용자 확인 뒤에 한다.
- 비밀값이 로그나 문서에 노출된 것을 발견하면 해당 값을 폐기·재발급해야 한다고 사용자에게 알린다. 값을 다시 출력하지 않는다.
- 단계가 막히면 우회하지 않는다(예: 보안 검사를 끄거나, 공개 범위를 넓히거나, 제한을 풀어서 통과시키기).
- 커밋과 푸시는 사용자가 허락한 뒤에만 한다. 증거 문서에 비밀값이 없는지 커밋 전에 한 번 더 확인한다.
