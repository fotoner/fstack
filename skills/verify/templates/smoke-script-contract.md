# smoke 스크립트 계약

실제 외부 서비스를 호출하는 확인 스크립트는 모두 같은 규칙을 지킨다. 사고로 게시, 과금, 알림이 나가는 일을 막고, 사용자가 실행 전에 영향을 읽을 수 있게 하기 위해서다.

## 규칙

1. **`--yes-live`가 없으면 아무 호출도 하지 않는다.** 필요한 것, 하는 일, 외부에 남는 영향, 추가 인자, 실행 명령을 출력하고 종료 코드 0으로 끝낸다.
2. 필요한 비밀값이나 설정이 없으면 외부 호출 전에 비어 있는 **변수 이름만** 알리고 비정상 종료한다. 값을 출력하지 않는다.
3. 모든 출력과 오류 메시지는 비밀값 마스킹을 거친다.
4. 통과 기준은 스크립트가 숫자로 판정하고 항목마다 PASS / FAIL을 출력한다. 하나라도 FAIL이면 종료 코드가 0이 아니다.
5. 외부에 남는 영향이 있으면(게시, 과금, 발송) 실행 전에 한 줄로 알린다. 테스트 계정, 삭제 방법을 함께 출력한다.
6. 유닛 테스트(`pnpm test`)가 아닌 별도 명령으로만 실행되고, 일반 테스트가 실수로 호출하지 못한다. 일반 테스트는 이 스크립트가 `--yes-live` 없이 아무 호출도 하지 않는다는 것만 확인한다.
7. 결과 요약(항목, 수치, 판정)을 사람이 증거 문서에 옮기기 쉬운 형태로 마지막에 출력한다.

## 계획 출력 예

```text
[smoke:<이름>] <제목>

--yes-live 인자가 없어 아무 호출도 하지 않았다. 실행하면 다음을 한다.

필요한 것
  - <환경 변수 이름 또는 파일>
하는 일
  1. <단계>
외부에 남는 영향
  - <게시, 과금 등>
추가 인자
  <--list-id <ID> 같은 설명>

실행: <패키지 관리자> smoke:<이름> --yes-live
```

## 구현 골격 (TypeScript 예)

```ts
interface SmokePlan {
  name: string
  title: string
  requires: string[]
  steps: string[]
  effects: string[]   // 외부에 남는 영향. 없으면 빈 배열
  options?: string[]
}

// --yes-live가 없으면 계획만 출력하고 null을 돌려준다. 호출하는 쪽은 null이면 즉시 끝낸다.
function startSmoke(plan: SmokePlan, argv = process.argv.slice(2)): { values: Record<string, unknown> } | null
```

프로젝트의 언어와 도구에 맞게 같은 형태로 만든다. 핵심은 "플랜 출력 함수 하나와 `--yes-live` 검사 하나를 모든 스크립트가 같이 쓴다"는 점이다.

## 통과 기준을 정하는 법

- 가능하면 계획 문서의 "지금 확인할 수 없는 가정"에서 가져온다. 가정마다 확인 스크립트와 기준이 하나씩 대응해야 한다.
- 비율 기준은 표본 수를 함께 적는다(예: 20건 중 18건 이상).
- 기준 미달일 때의 행동(설계 변경, 정책 확정)을 계획에 미리 적는다. 미달을 "일단 통과"로 처리하지 않는다.
