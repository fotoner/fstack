# 컨실 검토 지시서: <대상 이름> r<N> (<모드>)

`~/dev/fstack/shared/delegate-brief.md`의 공통 틀 위에 아래를 채운다. 위원마다 같은 지시서를 보낸다.

```markdown
Review only. 파일을 고치거나, 커밋·푸시·PR 댓글을 하거나, 하위 에이전트를 띄우지 않는다.

## 대상
- <파일 경로 또는 diff 명령. 원격이면 전문을 아래에 붙인다>
- 판: r<N> (직전 판: <경로 또는 없음>)
- 의도: <한 줄>
- 범위 밖: <한 줄>
- 이미 돌린 검사: <명령과 결과 / 없음>
- 함께 읽을 근거: <조사 보고서 등. 원격이면 요약을 붙인다>

## 보는 것
<모드별 질문. 예(design): 근거와 맞지 않는 규칙, 서로 충돌하는 규칙, 빠진 실패 경로, 실제로 호출되지 않을 트리거, 하네스(Claude Code·Codex·Pi·T3)에서 실행할 수 없는 절차, 사용자가 이미 정한 규칙과의 충돌, 과잉 명세>
범위를 키우는 제안은 nit으로 적는다.

## 심각도
- blocker: 의도한 사용에서 틀리게 동작하거나 해를 끼친다.
- should: 사용자가 실제로 겪을 문제다.
- nit: 나머지(다른 경로, 드문 경우, 작은 비용, 취향).

## 응답 형식
VERDICT: APPROVE 또는 CHANGES
SCORE: <0~10>/10
요약: <3줄>
<위원 접두어><번호> [blocker|should|nit] <위치(파일:줄 또는 절)> <주장>. 시나리오: <구체적으로 어떻게 깨지는가>. Fix: <가장 작은 수정>

## 이전 라운드 (r2부터)
<원장: ID, 처리, 근거>
이전 ID마다 `해소` 또는 `미해소: <이유>`를 먼저 적고, 바뀐 부분에서 생긴 새 문제만 지적한다. 이미 해소된 문제는 다시 지적하지 않는다.
```

위원 접두어: Opus `O`, Sol `S`, Gemini `G`. 라운드 번호를 붙인다(예: `S2-3`).
