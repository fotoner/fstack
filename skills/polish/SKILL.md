# polish

한국어 글은 다른 회사 모델 1인의 첨삭을 받아 독자가 한 번에 읽을 수 있게 다듬는다. 목표는 읽는 사람의 부담을 줄이는 것이고, AI 탐지기 점수는 기준이 아니다. 첨삭자는 걸리는 문장을 짚고 수정안을 낸다. 고치는 것은 작성자다. 리뷰 규칙(읽기 전용, 판 고정, 원장)은 `~/dev/fstack/skills/council/SKILL.md`를 따르고, 아래가 우선한다.

`spec`과 `proto`는 산출물을 보이기 전에 이 스킬을 거친다. 그 밖의 문서는 사용자가 말하거나 `~/dev/fstack/local/core.md`가 정할 때 거친다.

## 쓰지 않는 경우

- 내용·논리·사실의 검토: `council`. 코드 변경의 리뷰: `sol-loop`.
- 번역, 새 글 쓰기, 내용을 더하는 보강, 맞춤법 검사만 필요한 글.
- 코드, 로그, 인용문. 남의 글을 검토만 요청받았으면 지적 목록까지만 돌려준다(C11).

## 첨삭자

- Gemini Hydrogen 최신 1인, 추론 단계 xhigh(`~/dev/fstack/local/routing.md` 1절 `editor`). ID를 적지 않고 `orchestrator_capabilities`로 확인한다. 사용자가 모델이나 단계를 말하면 그것을 쓴다.
- 부를 경로가 없으면 다른 모델로 바꾸지 않고 막힌 이유를 보고한다. 다른 스킬의 단계로 불렸으면 산출물은 그대로 내고, 보고 첫머리에 첨삭 미실행과 이유를 적는다. 첨삭자는 하위 에이전트를 띄우지 않는다.

## 예산

- 기본 2라운드, 최대 3라운드. 1라운드는 전체를 보고, 이후 라운드는 바뀐 문장과 열린 지적만 본다.
- 3라운드는 blocker가 열려 있거나 사용자가 요청할 때만 연다. nit만 남으면 일찍 끝낸다.
- 고쳐 쓰기를 거듭할수록 글은 원문에서 멀어진다. 예산 소진은 승인이 아니다.

## 1. 준비

- 글은 파일에서 지금 본문을 다시 읽는다. 방금 내가 쓴 글도 기억으로 보내지 않는다. 판을 보존한다(`r0`).
- 기계 점검을 먼저 돌린다: `python3 -I ~/dev/fstack/skills/polish/scripts/polish_check.py pre <파일>`. 내 글이면 `--fix <판>`으로 연결어미 뒤 쉼표를 걷은 판을 `r0`로 삼는다. 남의 글이면 고치지 않고 쉼표 위치를 지시서의 기계 점검 칸에 넣는다. 스크립트가 실패해도 첨삭은 하고, 보고 첫머리에 기계 점검 미실행을 적는다.
- 지시서에 넣을 것을 적는다: 글의 종류와 독자, 문체(경어 단계 포함), 손대지 않는 것(용어, 수치, 인용, 코드, 고유명사).
- 기준의 우선순위: 사용자가 준 글 표본이나 프로젝트 취향 문서(C13) > 글의 종류 > `templates/editor-brief.md`의 기본 기준. 앞의 것이 있으면 지시서에 전문을 넣는다.

## 2. 라운드

- T3에서는 라운드마다 새 `delegate_task`(`role: "review"`, `mode: "async"`, 새 `clientRequestId`). 이전 스레드에 이어서 묻지 않는다. T3 밖에서는 그 하네스의 첨삭자 실행 경로 하나를 쓰고 ID를 남긴다.
- 지시서는 `templates/editor-brief.md`를 채운다. 글은 전문을 넣거나, 같은 호스트의 첨삭자에게는 보존한 판의 경로와 sha256을 준다. 큰 글을 원격 첨삭자에게 보낼 때는 `~/dev/fstack/local/routing.md` 3절의 파일 전달 경로를 쓴다.
- 첨삭이 도는 동안 글을 고치지 않는다. 완료 알림을 기다리고 폴링하지 않는다. 타임아웃·오류·무응답은 승인이 아니다.
- 다음 라운드는 예산이 남았고, blocker·should가 열려 있거나 그것을 고친 글이 아직 승인받지 않았을 때 연다. nit만 고쳤으면 열지 않는다. 1라운드 지시서, 원장(`fixed:` / `disagree:` / `declined:` + 근거), 바뀐 문장의 전후, 지금 전문을 보낸다.

## 3. 지적에 답하기

- 지적마다 원문 문장을 다시 읽고 직접 판정한다. 첨삭자의 수정안은 제안이다.
- 동의: 그 문장만 고친다. 수정안을 쓰기 전에 사실, 수치, 고유명사, 인과의 방향, 부정, 서법(단정·추측·당위), 인용이 원문과 같은지 본다. 하나라도 달라지면 직접 고쳐 쓴다.
- 반대: 이유를 한 줄로 적는다. 다음은 첨삭자가 뭐라고 붙였든 nit이다: 뜻이 분명한 문장의 낱말 취향, 한 번 쓰인 접속어·피동·'의'·'것', 정확한 한자어와 전문 용어, 필자가 의도한 문체.
- 반영한 뒤 `polish_check.py post <r0> <지금 판> --apply`를 돌린다. 새로 생긴 연결어미 쉼표는 스크립트가 걷는다. 서법 소실이 나오면 그 문장을 원문의 단정·추측·당위로 다시 고친다. 같은 문형의 반복, 다른 상투어, 순우리말·구어체로 바꾸기는 눈으로 본다.
- 바뀐 문장 수와 전체 문장 수는 `post`의 값을 쓴다. 절반을 넘으면 반영을 멈추고 사용자에게 보인다. 그 정도면 첨삭이 아니라 다시 쓰기다. 루프를 끝내려고 동의하지 않는다.

## 4. 끝내기

- **합의**: 지금 글에 APPROVE, 열린 blocker·should 없음, 내 우려 없음.
- **교착**: 같은 지적이 두 번 주고받은 뒤에도 갈리거나 예산이 끝남. 양쪽 입장을 2~3줄씩 보이고 사용자가 정한다.
- 내 글이 아니면 판을 따로 만들고 원문 파일을 덮어쓰지 않는다. 커밋·게시는 사용자가 말한 단계까지만 한다(`ship`).
- 보고: 라운드 수, 실제 첨삭자(모델과 단계), 판정, 기계 점검(정리한 쉼표 수, 서법 소실), 바뀐 문장 수와 전체 문장 수, 바뀐 문장의 AS-IS → TO-BE(많으면 대표 5개와 판 경로), 거절한 지적과 이유, 남은 것.
