## 공통 규칙

1. **자기 담당 경로만 고친다.** 아래 "읽기 전용" 경로와 다른 모듈의 공개 인터페이스(`index.ts`) 시그니처는 바꾸지 않는다. 바꿔야 하면 **최종 보고의 "요청 사항"** 에 적는다(오케스트레이터가 다음 웨이브 전에 반영한다).
2. 테이블·칼럼이 더 필요하면 **자기 예약 번호의 마이그레이션**(`migrations/000N_이름.sql`)을 새로 만든다. 남의 테이블은 바꾸지 말고 요청 사항으로 적는다.
3. **의존성 추가 금지**(`<패키지 파일과 잠금 파일>` 읽기 전용), **git commit 금지**, **비밀값 기록 금지**, **유료 API 호출 금지**.
4. <프로젝트 불변식. 예: 트랜잭션 안 await 금지, 시각은 time 모듈로만, 오류와 로그는 redact를 거친다.>
5. 끝나면 만든 파일, 실행한 검증과 결과, 남은 문제, 요청 사항을 보고한다(`worker-report.md` 형식).
6. 모든 작업자는 `<계약 예시 fixture 경로>`의 예시가 **자기 모듈의 입출력 스키마를 통과하는지** 테스트한다.

## 비밀값·로그 규칙

- 비밀값(토큰, API 키)을 **파일에 쓰지 않는다**: 소스, fixture, 테스트, 문서, 로그, DB 어디에도.
- 설정 객체를 통째로 로그에 찍지 않는다. <마스킹 헬퍼>를 쓴다.
- 오류를 문자열로 만들 때 <redact 헬퍼>를 거친다.
- 테스트에 가짜 키가 필요하면 비밀 패턴에 걸리지 않는 형태로 `test/` 안에만 둔다.

## 네트워크 규칙

- 외부 HTTP는 <래퍼>로만 한다. `fetch`를 직접 부르지 않는다.
- 테스트 러너는 루프백 외 연결을 예외로 막는다. 테스트 서버는 `127.0.0.1`의 임시 포트에 띄운다.

## 테스트 작성

- 위치: `test/<모듈>/…test.ts`. e2e는 `test/e2e/`.
- 공용 도우미: <makeTestDeps, seed 등>. 필요한 것만 덮어쓴다.
- 새 마이그레이션을 만든 담당자는 빈 DB 생성, 이전 웨이브 DB에서의 업그레이드, 자기 테이블의 제약을 테스트한다.
- 외부 응답은 fixture나 mock으로 대체한다. 실제 API·실제 사이트 접속 테스트를 만들지 않는다.
